# CHANGELOG.md

Full chronological history of the architecture refactor. Not required reading for a normal task — `AGENTS.md` already reflects the *current* state of every module. Check here only if:
- you're unsure whether something was already tried, tested, or reverted
- you need to understand *why* a module ended up structured the way it is
- you're about to propose something and want to check it's not already covered in `AGENTS.md` Section VIII (Rejected / Settled Questions) first — that table is the short version of what matters most from this log

| Stage | Changes |
|---|---|
| **1. Bugfixes** | Follow subscribes to `flipped` event instead of reading `parent.flipX` in `update()`; `screenToWorld()` ordering fixed (was duplicated inline for the cursor before its own definition); empty `Sound:update(dt) end` removed (Sprite:update already checks `if component.update`); ParticleEmitter fake-parent `emit` forwarding fixed; all 7 components migrated from raw event-name strings to `Events.lua` constants |
| **2. Hot-reload removal** | `ModLoader.reloadAll()` deleted — fragile `package.loaded[nil]` pattern with no real use case; matching `package.loaded[...] = nil` lines removed from `SpriteLoader.lua`, `ShaderLoader.lua`, `Generator.lua`; `ModLoader` return value discarded in `Main.lua` |
| **3.1 Animation + Spritesheet merge** | Two components did near-identical quad-rendering (`Animation.lua` row-based + timing, `Spritesheet.lua` grid-based + static `setFrame`). Merged into a single `Spritesheet.lua`; `Animation.lua` deleted. Data files switched from `component = "animation"` to `component = "spritesheet"`, keeping the `tags`→animation indirection (state name ≠ animation name) intact. Quad generation unified as grid-based (`columns`/`rows`), with auto-inference from image dimensions when omitted and `assert` validation against actual image size when given explicitly (catches silent mis-sliced spritesheets). `ParticleEmitter` switched from directly constructing `Animation.new()` to lazy-requiring `ComponentRegistry` inside `_spawn()` to avoid a circular dependency, then calling `ComponentRegistry.create("spritesheet", data)`. |
| **3.2 Tweens + Tween merge** | `Source/Helpers/Tweens.lua` (pure-data `Tween` class + easing functions) and `Source/Sprite/Components/Tween.lua` (event-driven component) were two files with the same name and split responsibility. Merged into one `Tween.lua`. Confirmed via grep that the `Tweens` module had zero consumers outside the component before merging. To avoid losing reusability of the `Tween` class/easing functions for future non-sprite consumers (UI, camera shake), the merged module exports `{Component, Tween, Easing}` instead of making them private locals. |
| **4. Generator split** | `Generator.lua` (242 lines) mixed three responsibilities: world-noise generation, terrain sprite construction, and prop spawning — plus it duplicated `SpriteLoader`'s sprite-construction logic by hand (manual `Sprite.new()` + direct `Spritesheet.new()`/`Collision.new()` calls, bypassing `ComponentRegistry`). Fix done in two parts: (a) extracted `SpriteLoader.instantiate(data, x, y, pngPath)` as a public function — the shared "turn a data table into a live Sprite" logic, with `loadAll()` rewritten to call it, no behavior change; (b) split `Generator.lua` into `WorldGen.lua` (pure `generate(config)`, single config-table argument instead of positional args, no sprite/component dependencies) and `WorldBuilder.lua` (exports only `build(tileData, config)`; internally calls private, non-exported `buildTerrain()` then `spawnProps()` in a fixed order, both routing through `SpriteLoader.instantiate()` instead of duplicating it; each resets its own collider registry before populating). `Generator.lua` deleted, `Main.lua` updated to the two new calls. |
| **5.1 Error hardening** | `Log.lua` created as the single extension point for error output (currently `print`, swappable later for file logging without touching callers). `Sprite:update()`/`Sprite:draw()` wrap every component call in `xpcall(component.fn, debug.traceback, component, dt)` instead of `pcall`, to get a full stack trace, not just a one-line message. Failed components get `component._broken = true` (skipped afterward, not removed) so a bug in one component can't crash the game or spam the log. `StaticSprite` draw and `sortY` update are intentionally left unwrapped — trivial arithmetic/engine calls, wrapping them would hide real engine/driver issues instead of surfacing them. `conf.lua` `console = false` confirmed as required for the VS Code Lua debugger; noted as a known tradeoff (hides `print()`/`Log.error()` output in release builds unless manually flipped for standalone runs). |
| **6.1 Sound pool audit** | `Sound.lua` had a dead `sourcePoolSize` field and used `base:clone()` per play. Investigated whether to build an actual object pool. Rejected — see AGENTS.md Section VIII for the reasoning. Dead field removed as cleanup (not as part of an optimization). |
| **6.2 DrawOrder double-call audit** | `DrawOrder.lua`'s module-level `sortBuffer` is only cleared past index `n` after `collect()` fills it, which loses data if `collect()` is ever called twice in one frame before `sort()`. Considered moving the clear to the start of `collect()` instead. Rejected — see AGENTS.md Section VIII for the reasoning; the underlying shared-state issue isn't fixed by reordering the clear, and there's no actual or planned double-call site. |
| **7. Shadow shader bleed bug** | Shadow:draw() (drawBehind) inherited the parent sprite's custom shader (Brightness) due to shared GPU state in Sprite:draw(). Brightness shader ignores the input `color`, so `setColor(0,0,0,alpha)` had no effect — the shadow rendered at full sprite colors. Fix: local `setShader(nil)`/restore in Shadow:draw(). A separate Shadow shader was considered and rejected: a shader can't draw a shadow below the sprite (single draw call), and component+shader adds complexity for no benefit. |
| **8. Dead code removal + build entrypoint consolidation** | AttackSystem: duplicated Weapon defaults removed (Weapon.lua is the single source of truth). Canvas/Destructible/ModLoader/ShaderLoader: dead functions/code removed. P4 LÖVE2D API fixes applied across 6 modules (wrong LÖVE method names in Sprite, Control, Shader, Follow, Canvas, Conf). WorldBuilder: consolidated into single `build()` export; `buildTerrain()` and `spawnProps()` are private locals called in fixed order, enforcing ordering by encapsulation. `buildWorldSprites` loop replaced with `SpriteLoader.instantiate()` — eliminates the duplicated `Sprite.new()` + `ComponentRegistry.create()` loop that had drifted out of sync. |
| **9. Event system fixes + utilities** | AttackSystem: enforce single-writer rule for `flipX` on weapon sprite — emit `Events.FLIPPED` instead of directly writing `ws.flipX`. Extract `Math.expSmooth(dt, smoothness)` from duplicated `(1 - math.exp(-dt / s))` across Follow and ProximityFade. Component order: move `control` before `collision` so collision resolution runs after Control moves the sprite. Burst particles migrated to module-level lifespan pipeline (survive parent removal from render lists). Minor: AGENTS.md doc reference updated, CLEANUP_PLAN.md gitignored. |
| **10. Performance (P5)** | Collision: replace `math.sqrt` distance checks with squared comparison (avoids ~350k sqrt calls/s measured). Shader: add dirty flag — skip redundant `shader:send()` when uniforms haven't changed. ComponentRegistry: swap linear scan for a lookup table. Tween: guard against nil tween values during init. Sprite: extract duplicate xpcall draw blocks into local `drawComponents()` utility with predicate filter. |
| **11. Fragile dependency patterns (P6)** | Spritesheet: remove `resolveSpriteSheet()` which scanned all of `package.loaded` comparing component table references — read `data.spriteSheet` directly. WorldBuilder: derive tile PNG path once via module identity lookup and pass to `SpriteLoader.instantiate()` so the data path is set before `Spritesheet.new()` runs. ParticleEmitter: search for `component == "spritesheet"` in particle data by name instead of assuming `components[1]`. Shader: derive uniform whitelist from the shader data file's `uniforms` table instead of hardcoded `{ "u_brightness" }`. Brightness shader: declare `u_brightness` in its `uniforms` field so the component discovers it. Brightness shader alpha fix: vertex `setColor` alpha now correctly darkens the sprite (was ignored). |
| **12. Path deduplication + error isolation (P7)** | Path: create `Source/Helpers/Path.lua` with `lua()`, `png()`, `moduleToPath()` helpers; replace 7 duplicated path-conversion patterns across Main, SpriteLoader, ParticleEmitter, ShaderLoader, WorldBuilder. Sound: wrap `love.audio.newSource` in `pcall` with `Log.error` fallback (missing/broken sound files can't crash). Spritesheet: wrap `love.graphics.newImage` in `pcall` for error isolation (matches SpriteLoader's existing pcall). Destructible: export `Destructible` table directly instead of `{ Component = Destructible, ... }` — consistent with all other components. ComponentRegistry: update `destructible` reference accordingly. Main: remove pointless `or {}` from `require` calls (data files always exist; `or {}` silently masked load errors). Fix `Path.png` to always append `.png` — `gsub("%.lua$", "") .. ".png"` handles inputs with or without `.lua` extension. |

| **30.07a Draw-path dedup** | Shader setup/teardown and tween-reading (scale/rot/flipX/alpha) were duplicated in `Sprite:draw()` and `SpriteSheet:draw()` — ~60 lines of near-identical code. Extracted to `Sprite:applyShader()` and `Sprite:getDrawContext()` methods; both callers unified through `self.parent -> sprite` pattern. ParticleEmitter spritesheets use a plain-table fake parent (no Sprite methods), so `SpriteSheet:draw()` guards with `parent.applyShader` / `parent.getDrawContext` existence checks. Removed unused `Log` import from SpriteSheet. |
| **30.07b Canvas management dedup** | `Mask.ensureCanvas` + `Shadow.ensureCanvas` were identical (check→release→newCanvas→setFilter). Canvas push/setCanvas/origin/clear→draw→restore block was duplicated in both `Mask.renderSilhouette()` and `Shadow.renderLayer()`. Extracted `Canvas.newCanvas(w,h)` factory and `Canvas.drawTo(canvas, fn, clearColor)` helper. Both Mask and Shadow use them via `Canvas.drawTo(canvas, function() ... end)`. |
| **30.07c Text rendering dedup** | Char-by-char text render (loop, space skip, charIndex/charWidth lookup, quad draw, color save/restore) was duplicated in `SpriteFont:draw()`, `Counter:draw()` label, and `TextEmitter.drawAll()` — ~80 lines repeated. Extracted `SpriteFont.drawText(ref, text, x, y, opts)` static. All three callers unified. Counter needed `ox` offset in caller (old code passed leftEdge as x, drawText treats x as pivot draw position). |
| **30.07d ValueParser internal dedup** | `ValueParser.value()` and `ValueParser.range()` duplicated the full parse chain (number→string→|→..→tonumber→fallback). Extracted `parseValue()` returning `{val, min, max}`. Both functions became one-liners delegating to it. |
| **30.07e inheritFlip regression fix** | Phase 1's SpriteSheet draw-path dedup removed direct `parent.flipX` read for plain-table parents (ParticleEmitter fake parents). Broke `inheritFlip` — particle spritesheets stopped flipping with parent. Added `elseif parent and parent.flipX then sx = -sx` fallback for parents without `getDrawContext`. |
| **30.07g findComponent predicate + getComponents** | Extended `Sprite:findComponent(type, predicate)` with optional predicate param. Added `Sprite:getComponents(type, predicate)` for iterate-all patterns. Refactored AttackSystem (3 destructible sites), Mask (silhouette + spritesheet), ParticleEmitter.detachAll, Shadow.renderLayer, WorldBuilder (collision getRect). ~30 lines removed. |
| **30.08 Pixel-based pivots** | `pivotX`/`pivotY` switched from normalized (0–1) fractions to pixel offsets or keyword strings (`"left"`/`"center"`/`"right"`, `"top"`/`"center"`/`"bottom"`). Added `Source/Helpers/Pivot.lua` — single `Pivot.px(value, size, default)` resolver replacing the `frame * pivot` multiply at every draw site (Sprite, SpriteSheet×2, SpriteFont, Counter×2, TextEmitter, ParticleEmitter×2, Follow, Mask, Main positionUI + boundary gizmo). SpriteFont `vAlign` math now reuses the resolved `oy` instead of `frameH * pivot`. Data files converted: normalized values mapped to pixels from their frame sizes (Character 0.5/0.75→8/12 on 16×16; props base 0.75→6 on 8×8 frames; trees 0.5/0.95→12/30 on 24×32), center-anchored UI/font sprites to `"center"`, Spark `0`→`"left"`, Pickaxe `1`→`"bottom"`. Defaults standardized to `"center"` across consumers. |
| **07.08a Composed post-process (Saturation→module + CircleMask)** | `Saturation.lua` converted from standalone `code` shader to a `type="color"` module (identical math; only the entry-point signature changed) so it can stack with other effects. New `CircleMask.lua` module — screen-space dithered black mask with a clear circle in the center (inverted spotlight): black outside, 1-bit ordered dither (2×2 Bayer, values offset +0.5 so solid regions are perfectly clean — a 0-valued cell was leaking single black pixels per block inside the circle) crossing the boundary into the circle, `u_circleRadius`/`u_softness` uniforms. Window→canvas transform passed per-frame (`u_canvasScale` = blit scale × output zoom, `u_canvasOrigin` = zoomed blit origin) and the shader snaps to whole canvas-pixel centers, so edge, dither cells and gradient steps follow the game pixel grid (nearest-neighbor look) at any window size and zoom — sub-pixel smoothing on the circle frame eliminated. Both marked `postprocess = true`; `ShaderLoader.loadAll` auto-composes every postprocess-flagged module (sorted by name) into ONE `"ScreenPost"` program with `priority = "postprocess"` — no program data file (`Content/Assets/Shaders/ScreenPost.lua` deleted); adding a screen effect is just flagging a module. `ShaderLoader.sendUniform` and `reset()` reach the merged uniforms unchanged. Main.lua: `love.wheelmoved` grows/shrinks `u_circleRadius` in canvas px (debug control), clamped to half the canvas diagonal, reset on restart; transform uniforms sent every frame in `love.draw`. |
| **07.08b Post-process hardening** | Explicit `order` field (number, default 0; tie-broken by name) replaces alphabetical stacking — Saturation `order = 10`, CircleMask `order = 20`, so the mask is the final screen effect. Dead `data.modules` program branch removed from `loadAll` — `postprocess = true` is the single way to declare a screen program. Screen transform centralised: new `ShaderLoader.setScreenTransform(scale, ox, oy)` broadcasts `u_canvasScale`/`u_canvasOrigin` to every effect declaring them (reused origin table, no per-frame alloc); Main calls it once in `love.draw` instead of two `sendUniform` calls. `getPostProcess()` docstring documents the single-slot invariant (exactly one postprocess program). |
| **07.08c Shader folder restructure** | `Sprite/` folder removed — it implied modules were sprite-only. Shader folders now encode module type, not usage: `Color/` (Saturation, CircleMask, Brightness, Tint, Silhouette), `UV/` (Skew), `Background/` (Caustic, the only standalone non-module). Postprocess modules live with color modules — `postprocess = true` + `order` declare screen usage, the sprite `shaders` array declares composition. Pure file moves: `Path.scanDirectory` is recursive and every reference is by data `name`, so zero code changes (verified via game load + harness). |
| **07.08d Satiety-driven circle mask** | Mouse-wheel debug control removed. Mask radius now driven by satiety: transparent at/above the low threshold (33%), blackening quadratically as satiety drops toward `lowSatietyMaskRadius` (canvas px, data field on player_stats, default 24) at zero. Target computed in the `VALUE_CHANGED` handler (same `f/low` curve as TimeScale/saturation/Zoom); radius eases toward it per frame (`Math.expSmooth`, 0.3s) so consecutive drains blend smoothly. Radius snaps to target at the off↔on boundary: pure easing from 0 swept through small (mostly-black) radii, flashing the screen black on entry and again when eating restored satiety — the snap confines the sweep to the visible-transition zone only. |
